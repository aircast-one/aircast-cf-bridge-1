# Contributing

aircast-cf-bridge is a single Cloudflare Worker (`src/worker.js`) plus a small
inline-style bundle (`src/styles.js`, generated by `scripts/bundle-css.mjs`).
There's no framework and no build step beyond that bundle — keep it that way.

## Setup

```sh
npm install
```

## Local dev

```sh
npm run dev     # wrangler dev
```

`wrangler dev` needs the same secrets a real deploy needs (`CF_APP_SECRET`,
`SIGN_KEY`, `DEVICE_TOKEN`) and a `SESSIONS` KV namespace — see the README's
Deploy section. Without them you can still exercise request routing, but the
WHEP bridge and link signing will fail.

## Tests

```sh
npm test        # node --test, no wrangler needed
```

`test/worker.test.mjs` runs against the Worker's exported handler directly, so
it doesn't need `wrangler dev` or live Cloudflare credentials. Add cases there
for new routes or auth paths — the routes table in the README is the contract
tests should match.

## Changing styles

If you touch the watch-page markup, regenerate the inlined CSS:

```sh
node scripts/bundle-css.mjs
```

`src/styles.js` is generated output — edit the source the script reads from,
not the generated file, or your changes will be overwritten on the next run.

## wrangler.toml

`compatibility_date`, the `SESSIONS` KV binding, and the `[[kv_namespaces]]`
block are what the one-click "Deploy to Cloudflare" button provisions
automatically. If you change a binding name or add one, update both
`wrangler.toml` and the `cloudflare.bindings` block in `package.json` — the
deploy button reads the latter to prompt for secrets, so they have to agree.

Secrets (`CF_APP_SECRET`, `SIGN_KEY`, `DEVICE_TOKEN`) are never committed —
set them with `wrangler secret put <name>` or let the deploy button collect
them.

## Deploying

```sh
npm run deploy   # wrangler deploy
```

There's no CI pipeline here — deploys are manual, straight from your machine
or the one-click button, into whichever Cloudflare account holds the Realtime
app. Run `npm test` before you deploy; there's nothing else gating it.

## Design constraints to keep in mind

- No dependency on `aircast-api`. Publish, signalling, and media all stay on
  Cloudflare so viewers keep working when the backend is down. A change that
  introduces a call back to aircast-api defeats the point of this Worker.
- Access is gated by the HMAC-signed `/watch` and `/whep` links, not by a
  session or login. Don't add stateful auth on top of this without a strong
  reason — it's meant to survive the backend being unreachable.

## Commits

Short, imperative `feat:`/`fix:`-style subject lines (see `git log`). No
attribution footers.
